# Authenticated owning selector metadata review — partial ESP-003

EvidenceService.reviewSelectors(request, selectors) accepts one to64 exact whole/text/page/time selectors, at most64KiB canonical UTF8. It accepts no caller EvidenceState, family history, scan status, source analysis or requireCurrent bypass. Existing authenticated request fields and Identity mapping apply. Each selected evidence reference must match authenticated scope.

The checked read audit takes Evidence's own project lock before reloading the current trusted credential directory and stored aggregate. Principal kind/ID and scope must remain the same; current read role is required again. Current purpose, clean scan, source revision, integrity metadata, representation digest and literal quote are validated using owning domain functions. All selected items fail together. Denial rolls back checked audit. The request, credentials and selectors are captured before awaits. Source histories/representations and credentials are not returned or audited; the audit contains only the selector count and ordinary authenticated request attribution.

The detached response contains scope/purpose, observed containing aggregate revision, selected exact selectors with dependency fingerprints and source-dependence analysis over the selected references. Analysis deduplicates exact bytes/shared ancestry and keeps unknown families unresolved; different files are not proof of independence. No raw family/independence history is exposed. An empty selector set is rejected. No effect/outbox or domain revision is created. Repeated calls are new checked reads, not cached attestations.

Before recursive owning validation the actual stored domain is bounded to8MiB canonical UTF8,4096 records per collection,512 source versions,64 families and8192 expanded family path visits. Response budget256KiB; excessive graphs reject whole review. Host CPU/heap/SQL result-size limits are still mandatory: in-process cloning/canonicalization is not a sandbox or memory isolation.

This is metadata review, not an original-byte read/decryption/hash check, real malware scan, extraction accuracy/truth determination, consent/rights decision or transferable permission. A fingerprint is a dependency key, not a signature. The owning locked observation can become stale after return. Sequential Identity observations do not atomically fence external policy revocation. The existing trusted identities callback/clock require host proofing/current mapping, deadlines/driver limits and isolation; this typed SDK adds no HTTP listener or deployed authentication service. Begun SQL is awaited; failed acknowledgement is unknown, not rollback proof. No historic-selector bypass, writes, family-admin routes, sends, publication or payments.
